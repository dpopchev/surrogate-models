## Hypothesis
Can one top-level paper.toml, read by pydantic-settings into typed section models in shared/, choose each section's figure and table variant and the common plot style, so make regenerates the paper with the chosen figures? Refuted if a variant or style value cannot be expressed as a typed field, or an invalid value loads without error.

## Outcome
shared/config.py loads paper.toml into a typed PaperConfig whose section choices are Literals, and shared/plots.py applies one paper-wide matplotlib and seaborn style from its plot section.

## Acceptance criteria
- AC1 Given a paper.toml, When shared.config.load_config() reads it, Then a typed PaperConfig is returned only when every key names an existing section folder and every value is an allowed choice -> W-013
- AC2 Given the plot section of paper.toml, When shared.plots.apply_style(config.plot) runs, Then matplotlib's rcParams carry the configured seaborn context, palette, serif font, usetex flag and figure width -> W-014

## Decisions
- 2026-10-05: paper.toml is the entry point that chooses which figures and computations are produced; each choice is a Literal scoped to what its module can draw or compute, so a new variant is added to the module and its Literal together
- 2026-10-05: values live in a top-level paper.toml, the schema in shared/config.py (pydantic-settings TOML source, env overrides PAPER__<SECTION>__<SUBSECTION>__<FIELD>); section keys are the folder names without their number prefix
- 2026-10-05: one shared matplotlib and seaborn style for every figure; text rendered with usetex (pdflatex, Latin Modern) to match the 11pt article; default palette colorblind
- 2026-10-05: the first slice is the config skeleton plus one real choice; further choices land with the figure or table that consumes them
