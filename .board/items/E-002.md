## Hypothesis
Do the two datasets, once preprocessed, support the outline's domains (BH 2D in (r_h, beta), NS 3D in (beta, lambda, rho_c)) and its Section 3.1 statistics? Refuted if a fixed column varies, D <= 0 occurs in a kept row, or a Section 3.1 number does not reproduce.

## Outcome
Preprocessed BH and NS tables, a frozen curve-grouped split, and the Section 3.1 numbers rendered from macros, all rebuilt by make from local/initial-data.

## Acceptance criteria
- AC1 Given local/initial-data/black-holes/black-holes-zero-phi0.dat, When the BH preparation runs, Then local/state/black_holes.parquet holds (r_h, beta) -> (M, D) with D > 0 and kappa, lambda2, phi0 asserted constant -> W-007
- AC2 Given local/initial-data/neutron-stars/neutron-stars.dat and the W-008 filtering rules, When the NS preparation runs, Then local/state/neutron_stars.parquet holds only converged, stable (beta, lambda, rho_c) -> (M, D) rows with D > 0 -> W-009
- AC3 Given both prepared tables, When the split runs with a fixed seed, Then local/state/split.parquet assigns every curve to exactly one of train, validation, test, held-out grid lines or domain edge -> W-010
- AC4 Given the prepared tables, When make compile runs, Then every Section 3.1 number in the PDF comes from a generated macro -> W-011

## Decisions
- 2026-10-04: only black-holes-zero-phi0.dat is used; kappa, lambda2 and phi0 are fixed settings, so BH is 2D in (r_h, beta)
- 2026-10-04: no solver and no field equations are available; only local/initial-data, which must be preprocessed first
- 2026-10-04: local/ holds runtime state (preprocessed tables, splits, trained weights, metrics) and survives make clean; build/ holds only what make builds and orchestrates into the paper -- a gate deviation from rules/python.md, recorded in CLAUDE.md
- 2026-10-04: Section 3.1 EDA describes the full filtered dataset; anything fitted from data (standardization statistics, data-driven thresholds, model selection) uses the training split only, and the paper states both
- 2026-10-04: tables are pandas DataFrames stored as parquet through pyarrow
