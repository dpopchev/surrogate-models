## Hypothesis
Can make produce one flat folder that keeps a drag-and-drop Overleaf project in sync (removed files listed), the whole paper, and one PDF per section with working references, all from a build/ grouped by section? Refuted if the upload folder needs files make did not put there, a re-run reports changes that did not happen, or a section PDF has undefined references.

## Outcome
build/assets/ grouped by section with each figure's PNG and wrapper sharing a stem; make overleaf filling build/paper/overleaf/ (flat, plus overleaf.zip) and listing the files added and removed since the last upload; make sections writing one PDF per section with references resolved through the full build; build/paper/article.pdf stays the whole paper.

## Acceptance criteria
- AC1 Given the prepared tables, When make assets runs, Then build/assets/<section>/ holds every generated file of that section, each figure's PNG and .tex wrapper sharing one stem -> W-031
- AC2 Given a previous upload list, When make overleaf runs with nothing changed, Then it reports 0 files added and 0 removed -> W-032
- AC3 Given a full build, When make sections runs, Then every PDF in build/paper/sections/ compiles without undefined references -> W-033
