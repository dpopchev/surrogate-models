## Hypothesis
Can every section folder build, test and hold its own settings and interim data as an independent module -- sharing code only through paperlib and data only through local/state -- with every figure variant and every table layout delivered as its own file under build/, while make deliverable keeps building article.pdf?

## Outcome
Each section folder is a module with its own make target, settings file and tests; shared code lives in the paperlib package; tables are typed objects stored in local/state and rendered from there; make figures and make tables write every variant as a standalone file under build/; make deliverable builds article.pdf throughout.

## Acceptance criteria
- AC1 Given make deliverable builds build/paper/article.pdf from shared/ and the scripts of 00_metadata, When shared/, the Python tools of 00_metadata and its preamble and notation files have moved into paperlib/ and make assets-same runs, Then it prints that every asset matches local/state/assets-baseline.sha -> W-134
- AC2 Given the tables of the paper are written as LaTeX strings by booktabs(), When every table writer builds a paperlib Table object instead and make assets-same runs, Then it prints that every asset matches local/state/assets-baseline.sha -> W-135
- AC3 Given every section's recipe lives in mk/paper.mk and its settings in paper.toml, When the developer runs make 41_neutron_stars, Then only the assets under build/assets/41_neutron_stars/ are rebuilt, from that folder's own .mk and .toml -> W-136
- AC4 Given each section script writes its tables and numbers straight into build/assets/, When each script stores them as JSON under local/state/<section>/ for a render step to write build/assets/ from and make assets-same runs, Then it prints that every asset matches local/state/assets-baseline.sha -> W-137
- AC5 Given the figure variants are drawn by make variants with one contact sheet per figure, When the developer runs make figures, Then build/figures/<section>/ holds every variant of every figure as its own PNG, 46 files and no contact sheet, drawn from local/state with nothing fitted -> W-138
- AC6 Given the table layouts and shapes are page images drawn by rerunning every section script, When the developer runs make tables, Then build/tables/<section>/ holds each table in each layout and shape as its own PDF, 40 files, rendered from local/state with no section script rerun -> W-139
