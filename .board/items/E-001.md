## Hypothesis
Does make compile turn the top-level chapter folders (LaTeX text plus the Python scripts beside it) into a flat, self-contained build/paper/article/ that compiles to a PDF and uploads to Overleaf as one zip?

## Outcome
One command produces an Overleaf-ready article from the agreed skeleton, including assets generated by scripts.

## Acceptance criteria
- AC1 Given chapter folders 00..80 with section stubs from the outline, a shared preamble and a stub refs.bib, When make compile runs, Then build/paper/article/main.pdf is produced with no LaTeX errors -> W-001
- AC2 Given a section script with its test beside it, When make compile runs, Then the asset it generates appears in the compiled PDF -> W-002
- AC3 Given a compiled build/paper/article/, When make compile finishes, Then build/paper/article.zip unpacked into an empty directory compiles to a PDF on its own -> W-003

## Decisions
- 2026-10-04: the paper is native LaTeX; build/paper/<flavour>/ is a flat copy of every .tex, .bib and generated asset
- 2026-10-04: text is edited in this repository; Overleaf is one-way (render and edit), changes come back by hand
- 2026-10-04: the first flavour is article (build/paper/article/); another flavour (e.g. revtex) is a sibling folder later
- 2026-10-04: chapter folders sit at the repo root; each section folder holds its text and the Python scripts that make its assets, each script with test_<script>.py beside it
- 2026-10-04: Python is a tool, not the product: a non-package uv project, no src/, no tests/, no wheel
- 2026-10-04: packages and macros shared by every flavour live in 00_metadata/preamble.tex; references in 00_metadata/refs.bib (natbib + bibtex), a stub the developer replaces
